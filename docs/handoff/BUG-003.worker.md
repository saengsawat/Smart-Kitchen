# BUG-003 worker report

Branch `bug-003-device-layout`, from main `b252862`. Implementation commit `e02dbb7`, this report is the final commit. Sonnet worker.

## What changed and why

Nothing at the bottom of S4/S5/S11/S12 knew how tall the floating tab bar is, and S7 never read the bottom inset. Now:

- `apps/mobile/src/navigation/TabBar.tsx` exports `TAB_BAR_HEIGHT` (66), `TAB_BAR_BOTTOM_OFFSET` (18), `tabBarClearanceFor(inset)` (pure) and `useTabBarClearance()` (reads `useSafeAreaInsets().bottom`). The bar itself now uses the two constants; its look is unchanged.
- Hook formula: `66 + 18 + insets.bottom + spacing.lg (16)`. Inset 0 gives 100, inset 34 gives 134.
- S4 `app/inventory.tsx`, S5 `app/inventory/[itemId].tsx`, S11 `app/shopping.tsx`, S12 `app/profile.tsx`: `contentContainerStyle={[styles.content, { paddingBottom: tabBarClearance }]}`. The hard-coded `spacing.xxl * 2` (64) is gone from all four. Per-screen paddingBottom is therefore 100 with no inset, 134 with a 34 inset (same on all four). In inventory.tsx only the hook import, the hook call line, the ScrollView prop and the removed style line changed; `handleConfirm` is untouched, so BUG-004's hunks do not overlap.
- S7 `app/add/scan.tsx` (layout and styles only, no strings):
  - Live-camera state now has a sand `styles.screen` root (was espresso). It holds a camera panel (`testID="scan-camera-panel"`, espresso, `height = round(0.55 * windowHeight)`, `flexShrink: 1`, `overflow: hidden`) that contains the camera (or the espresso2 placeholder) filling it absolutely, the back/title row, and the brackets. Brackets are centred in the panel (`top: 50%`, `marginTop: -75`, height 150, 20% side insets as before). The hint sits directly under the panel; its colour is now `colors.ink2` because cream on sand is unreadable. A `flex: 1` spacer (sand) separates the hint from the sheet.
  - Sheet (`testID="scan-fallback-sheet"`) is wrapped in `KeyboardAvoidingView` (`behavior` "padding" on iOS, "height" otherwise) and its `paddingBottom` is `insets.bottom + spacing.md`. The panel's `flexShrink: 1` lets it give up height when the Android window resizes for the keyboard, so the sheet stays on screen.
  - Permission-denied, miss and confirm states are unchanged (they keep `camScreen`).
- Test support: `react-native-mock.ts` gained `KeyboardAvoidingView`, `Platform` (OS "android") and a settable `useWindowDimensions` (`setMockWindowDimensions`); new `safe-area-mock.ts` with `setMockBottomInset` and `useSafeAreaInsets`.
