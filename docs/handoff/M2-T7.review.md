Reviewer: an independent sub-agent (Opus, rule 23: the create path's idempotent replay). Branch `ticket/M2-T7`, commit b90aeda, base 40ff295. Read-only review. Squashed to main as 9e41b98.

**Verdict: PASS**

## Acceptance criteria

- **(a) Lot label.**
  - Optional, validated in `planCreation` with the same rules as `displayName`:
    - the label is trimmed;
    - it is refused with `INVALID_FIELD` on `lotLabel` when empty, longer than 64 code points (`[...label].length`), or containing `\p{Cc}`.
  - Stored on the lot insert inside the existing create transaction.
  - S8 sends "{qty} {unit}" only when `planScanQuantity` took the package-size branch with `userTyped: true`. A typed size in an unsupported unit falls to count-only and sends neither field.
  - Met.
- **(b) Quantity origin.**
  - On `BARCODE`, `USER_TYPED` maps to the server constant `barcode-scan-typed-size`, and `PRODUCT_DATA` or absent maps to `barcode-scan`.
  - Any value on `MANUAL`, and any unknown value, is refused with `INVALID_FIELD` on `quantityOrigin`.
  - Only the source string changes; tier and amount do not. No client source string is ever stored.
  - Met.
- **(c) Replay.**
  - `findByKey` selects `l.label` from the creation lot (joined by `t.lot_id`), and `sameCreation` compares it. It already compared `provenance_source`.
  - A request made before this change, with no label and no origin, plans `null` and `barcode-scan`, which matches the old rows. The existing replay tests pass.
  - Both sides are trimmed. There is no Unicode normalisation, which is correct for idempotency.
  - `PRODUCT_DATA` and absent replay as each other, since they are the same stored fact.
  - The M2-T6 move-aware location join is unchanged.
  - Met.
- **(d) Item detail.** The detail DTO already maps `inventory_lots.label`, and the DB test shows "248 g" on GET. No code needed. Met.

## Findings

1. **Low, follow-up.** A label with a lone surrogate (for example `"\ud800"`) passes `\p{Cc}`. node-pg encodes it as U+FFFD, so an identical retry answers `IDEMPOTENCY_KEY_CONFLICT`. `displayName` and `productRef` already behave this way, so this ticket didn't introduce it. A separate ticket should refuse `\p{Cs}` (or non-well-formed strings) on all create text fields.
2. **Low.** The route's maxLength of 256 means an untrimmed label over 256 characters gets the generic schema 400 instead of `INVALID_FIELD` on `lotLabel`. Acceptable.
3. **Info.** Replay compares the lot's current `label`, and migration 0006 grants UPDATE on it, though no code writes it today. A future label-edit ticket needs a creation-time snapshot, like M2-T6's location.
