# M2-T1 review: identity port, request context, default-deny authorization, first read endpoint

**Reviewer:** independent Opus session, read-only, adversarial. **Branch:** `m2-t1-identity-port` @ `55edbcb`. **Baseline:** `main` @ `131f117`. ## Verdict

**PASS WITH FIXES** (re-review required). The tenancy and authorization core survived every attack constructed, including five mutation checks in a scratch copy. Three defects must be fixed before acceptance, one blocking: the compiled API does not start.

## Findings

**F1 (blocker) The API cannot be started.** `apps/api/src/http/routes.ts:14` value-imports `INVENTORY_ITEMS_PATH` from `@smart-kitchen/contracts`, whose `package.json` points `main` and `exports` at `./src/index.ts`; `node dist/server.js` fails with `ERR_UNKNOWN_FILE_EXTENSION` before any refusal line. `inventory-snapshot.ts:43` adds a second instance through `repository.ts`, which value-imports `@smart-kitchen/domain`. Regression: on `main` the compiled server loads and listens. The acceptance criterion "NODE_ENV=production SK_IDENTITY=fixture exits non-zero with a clear message" holds only inside `startServer()` in a unit test. Fix needs an architect scope ruling (`packages/*/package.json` are outside the ticket's scope): real builds for the workspace packages with `exports` pointing at `dist`, or a TS loader, or conditional exports; plus a test that spawns the compiled entry point.

**F2 (major) Every 500 logs `{"type":"NonError","message":"[object Object]","stack":""}`.** pino applies `formatters.log` before `serializers`; `redactLogObject` reshapes the Error into a plain object, then `redactErrorForLog` receives a non-Error. Fails safe (nothing leaks) but destroys type, message and stack; `redactErrorForLog` is dead code on the only path that uses it. There is no test for the 500 path at all. Fix: drop the `err` serializer and rely on the Error branch of `redactValue` (or apply the function inside it); add a 500-path test asserting a generic body with correlation id and a scrubbed but present `err.type` and `err.message`.

**F3 (major) The production refusal is case and whitespace sensitive.** `registry.ts:51-53` compares `NODE_ENV === "production"`; `Production`, `PRODUCTION`, `prod`, `"production "` and unset all allow the fixture adapter. `registry.test.ts:88` pins `Production` as not-production deliberately; the reviewer disagrees: the single control between three public tokens and a deployed process should be an allowlist (`development`, `test`, unset). Related for the architect: D-022 says the fixture identity is "compiled out of production builds"; it is not, only its selection is guarded. Reconcile the wording or ticket a build-time exclusion.

**F4 (minor) Deleting the redaction denylist layer breaks no test.** Removing `formatters: { log: redactLogObject }` leaves 74 tests green; the layer is installed (verified by probe) but not pinned. Fix: one request-level test asserting `displayName` and `email` come back `[redacted]`. Also document that value-shape scrubbing does not catch a name embedded in free text.

**F5 (minor) `TenantSessionOptions.role` is a production-reachable RLS off-switch** used only by its own test, whose title asserts the opposite of its body. Remove the option; fix or delete the test.

**F6 (minor) `CORRELATION_ID_HEADER` defined twice** (contracts `errors.ts:40` and api `logging.ts:50`). Import the contracts one.

**F7 (minor) `apps/api/src/server.test.ts`** is outside file scope and undeclared in the report. Accepted; declare it.
