### Findings
- **F1 (HIGH, required):** `ledger.ts:431` unfiltered `...input` spread let a caller forge `systemFlag` onto a user row (and persist arbitrary unknown fields) — making the correction-rate KPI forgeable. Repro executed: forged `OVER_CONSUMPTION` flag appended, `reconcile ok: true`.
- **F2 (MEDIUM, required):** `rehydrateInventoryItem` accepted payload-incoherent stored rows — most seriously a row whose `qtyDeltaMicros` contradicts `qtyDelta` (rehydrated to 1999.25 lb vs the displayed 2 lb; `reconcile ok: true`). Also accepted: sign-vs-type violations, out-of-range rows, forged clamp-namespace keys.
- **F3 (LOW):** `quantity.ts` comment overclaimed the decimal-view exactness guarantee (holds per delta, not for accumulated balances; true threshold ≈100 appends at the per-delta cap, not ~1e6).
- **F4 (LOW):** `appendTransaction` deep-froze the caller's own nested input objects (shared references).
- **F5 (INFO):** two report inaccuracies (fast-check does have one transitive dev dep, `pure-rand@8.4.2`; the §8.5 threshold figure).

### Design-soundness opinions (reviewer, ratified by architect)
- **Clamp semantics — strong agreement:** full-magnitude recording + system residual `ADJUSTMENT` preserves the user's statement and makes the correction-rate KPI a direct query; per-lot clamping correctly avoids inventing a lot-selection policy; clamping all decreasing instruments (ADJUSTMENT included) keeps INV-LEDGER-4 unconditional. Recommended restating INV-LEDGER-4's wording (ambiguous as written) — done at acceptance.
- **`IDEMPOTENCY_KEY_CONFLICT` — agree:** rejecting a reused key with a different payload is strictly stronger than silent replay. Caution recorded: `isSamePayload` compares `occurredAt` as a raw string, so equivalent instants in different ISO forms conflict — decide deliberately at the sync layer (noted on ADR-010).
- **No ledger-level gate on unconfirmed `AI_INTERPRETATION` rows — agree:** confirmation belongs at the `AIObservation` boundary (INV-CONF-1); the observation boundary is therefore load-bearing and needs its own invariant test when built (backlog note).
- **bigint micro-units — "the single best decision in the ticket":** float deltas would make INV-LEDGER-1 order-dependent and force an epsilon onto an inventory invariant. No balance cap; honest comment instead (accepted).
- Also noted: total-function API means discarded `AppendResult`s silently lose writes — a mustUse-style convention for the service layer (backlog note); a caller can still *claim* `actor: system` (cosmetic once `systemFlag` is unforgeable) — service-layer authorization question (backlog note).
