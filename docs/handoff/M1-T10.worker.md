## 2. One deviation worth flagging: item (i) touched two domain files beyond the file-scope bullet

The ticket's file-scope line names only `packages/domain/src/allergens/corpus.test.ts` for domain, but item (i)'s own text explicitly instructs moving the mirror into `test-support.ts` — so that file is touched as instructed. Reaching it from `packages/adapters` needed one more, narrower step I want to be explicit about:

`packages/domain/package.json`'s `"exports"` map exposes only `"."` — no subpaths. A relative import from `packages/adapters` straight into `packages/domain/src/allergens/test-support.ts` type-checks fine under vitest's esbuild transform, but fails `pnpm typecheck` (`tsc -b`) with `TS6059`/`TS6307` (`rootDir` violations under composite project references) — I verified this directly (built it, watched it fail, reverted). The only typecheck-safe route is a bare `@smart-kitchen/domain` import, which only reaches what `index.ts` re-exports. So `packages/domain/src/index.ts` gained one small, clearly-commented block re-exporting exactly `RECOMMENDATIONS_CORPUS_CASE_FILES`, `RECOMMENDATIONS_CORPUS_CASES`, and `ScreeningCase` (as `RecommendationsCorpusCase`) — corpus *data*, not part of the screening engine's own surface, and not a general "test-support is now public" change (every builder function in `test-support.ts` stays unexported, exactly as before).

This also meant `packages/adapters/package.json` needed `@smart-kitchen/domain` as a **devDependency** (only the new test file uses it) and a matching `references` entry in its `tsconfig.json` — both narrow, internal-workspace additions (rule 11: not a new external dependency, and adapters depending on domain is the direction ARCHITECTURE.md already allows).

If the architect would rather this exposure not exist on `packages/domain`'s public surface, the alternative is widening `package.json`'s `exports` map with a dedicated subpath instead (e.g. `"./allergens/test-support"`) — a smaller diff in one sense, a wider one in another (it makes the *whole* file importable, not three named items). I judged the index.ts re-export the narrower of the two and went with it; flagging the choice rather than silently making it.
