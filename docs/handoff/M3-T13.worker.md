- Both are variable fonts used through `fontWeight`, like the old pair. Android variable-weight rendering is still unverified on a device. Bodoni's `opsz` axis stays at its default (RN has no optical-sizing control).

## Differences from v6 and things to know

1. **Icons.** The app has no icon library (rule 11), so v6's line icons are missing: Add rows (pen, receipt, camera), the avatar initials, the Inventory search button (already hidden, F18), the sparkle on the tray heading, the scan icon on the Add block is the existing View-drawn one. Tab icons keep the existing View glyphs, with stroke 2.3 on the current tab.
2. **Food photos** stay out. Tiles carry a first-letter placeholder in Bodoni (inventory rows 56px, shopping rows 48px, tray 44px).
3. **Home** shows a masthead "SMART KITCHEN · {weekday}" plus the ink avatar and the rule. v6's "Chen household" needs data Home does not read, and the headline "Tonight: ..." belongs to the held dashboard. The empty state is the v6 `.emptyst` panel with the existing strings. The avatar has no initials (as before).
4. **Add food.** v6's "Coming soon" heading and the two new toasts are PROPOSED strings not yet in the deck, so I kept the deck's phase tags (`fast-follow`, `future`), toasts and accessibility labels, and put the two rows in the ruled list under "Type it in" with the v6 `.arow.soon` look (no heading). Adopting the heading is a small follow-up once M3-E0-T6 lands it in the deck.
5. **Expiry pill layout, tests edited.** The row used one text node `"{qty} · {urgency}"`. The v6 `.days` pill needs its own element, so `inventory-screen-expiry.test.ts` and `item-detail-expiry.test.ts` now assert the pill text (`"expired"`, `"may be expired"`, `"use today"`, `"tomorrow"`, and the lot label plus `"expires today"` etc.) separately. Same cases, same wording checks, row accessibility labels untouched. No INV test touched.
6. **Tab bar** is full width and in ink, not floating. `TAB_BAR_HEIGHT` is now 56 (8 + 48), `TAB_BAR_BOTTOM_OFFSET` 20 (minimum bottom padding), clearance = 56 + max(inset, 20) + 16. Five tests that pinned 134 (inset 34) now pin 106, and `tab-bar.test.ts` pins the new constants. The architect flagged this constant for revisiting; tokens.md section 10 needs the new formula.
7. **Blocked Add on Scan** becomes an outlined ink button (it was a different colour from the terracotta primary; both are ink now, so the existing "not the primary style" assertions would have collapsed). Two scan tests only had their comments and titles reworded ("terracotta" to "ink primary").
8. **Scan confirm sheet verdicts** now sit on the v6 panels: blocked evidence rows on the block bar (`dangerBg`, 1.5px `danger` border, 10px corners), unknowns on the amber verdict panel, allowed on a hairline-ruled line. Same text, same chips, no icon added. The block bar has no warning-disc icon (v6 draws one); words carry the meaning.
9. **Tier chip colours.** The scan sheet's `provChipSmall` painted every tier amber. All chips now use the tier's own pair (Fact green, Est. amber, AI purple). Reviewer: this is a colour-role fix, intended.
10. **Danger used for non-allergen validation removed.** Typed-quantity invalid input (item detail), invalid package size (scan) and the manual-add name error used `danger`. v6 and tokens.md section 5 reserve it for allergens, so they are now ink (heavier underline, bold hint). Same messages, same behaviour.
11. **Fast-follow tags** on the profile screen were purple (`ai`); purple is AI-only, so they are now `tile` tags.
12. **Not pixel-equal:** letter spacing and Bodoni optical sizing (RN has no `font-optical-sizing`), the camera gradient (solid `cameraBg`, no new dependency), the nutrition "per serving" label and the "Nutrition & allergens" caption layout (app data shapes differ). A real-device pass is still owed (camera, Android variable-font weights).
