The planner delivers the ticket's substance: worked example asserted exactly; FEFO/FIFO ordering is a genuine total order; allocations are capped at the **derived** lot balance so a planner-produced plan provably cannot clamp; the key scheme is injective and outside the reserved `::` namespace (exhaustive 4 680-base × 3-index collision search: 0 collisions); explicit-field copying in `consumptionInputsFromPlan` correctly applies the M1-T1 F1 lesson (8 smuggled fields all dropped). ## Findings
- **F1 — MEDIUM, required (fixed):** duplicate `lotId` entries in `item.lots` pass `reconcile()` (it has no duplicate-lot check) and the planner allocated the same stock twice, returning `ok` with Σ|allocations| = 2 × on hand. Repro: `{ ...base, lots: [base.lots[0], { ...base.lots[0] }] }`, request 2.0 against 1.0 on hand → `ok`, `allocatedMicros 2_000_000n`. **Fix:** `seen` set over `item.lots` → `DUPLICATE_LOT` before any candidate is built. Re-review: refused; 3-way / late / zero-balance duplicates refused; lookalike ids (`"L1"`, `"L1 "`, `"l1"`, `"L10"`) correctly distinct; healthy 1–8-lot aggregates unaffected.
- **F2 — LOW, backlog:** `planLotConsumption` is not total on five malformed-aggregate shapes (`null` lot element, missing `currentQty`, `number` micros on lot or row) — `TypeError` from inside `reconcile` (`derive.ts`), out of this ticket's scope. Fails loud, not open.
- **F3 — MEDIUM-LOW, required (fixed):** the hand-built-plan overdraw guard in `validateAllocation` was conditional on `typeof lotBalanceBeforeMicros === "bigint"`; omitting or mistyping the field skipped it, inputs were produced, and applying them **produced a real clamp** (proved). **Fix:** non-bigint balance ⇒ `INVALID_FIELD`, comparison unconditional. Re-review: `number`, `"500000"`, `null`, `undefined`, `500000.5`, `NaN` all refused; planner-produced plans still convert (2 000/2 000 in the rebuilt property).
- **F4 — LOW, required (fixed):** `request.qtyMicros` read three times; a type-shifting getter yielded a plan with `number` fields (caught downstream, but the M1-T6 F1 class again). **Fix:** single read into locals. Re-review: 1 read; all fields `bigint`; `amount` and `policy` getters also single-read.
- **F5 — INFO:** final tie-break is positional (`item.lots` order), not intrinsic; determinism is borrowed from `loadInventoryItem`'s `ORDER BY created_at, id`. Correct today; backlog: compare `lotId` so plans are a pure function of lot data before a second read path (cache/batch/projection) exists.
