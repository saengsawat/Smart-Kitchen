## Method

1. Read `:root` (lines 12-37) and the full `<style>` block (lines 10-409) of the prototype, plus `design-direction.md` (all sections), `design-principles.md` (all), and `M3-E0-T1.review.md` (the review record this ticket's inputs come from), per the dispatch's "read first" list.
2. Compared every row of design-direction §0's v2 token sheet against the literal `:root` declaration. **Result: zero drift.** All 15 §0 rows match `:root` exactly (hex-for-hex), so **`design-direction.md` §0 was not edited**, there was nothing to correct.
3. Built the token table (tokens.md §1) directly from `:root`, assigning role/allowed/forbidden uses from the design-direction rules (scarcity rule, allergen-only rule, AI-exclusivity rule) and from the CSS comments already in the prototype (e.g. "the one large dark surface allowed", "purple appears nowhere else").
4. Computed WCAG 2.x contrast for 35 pairs with a `node -e`-style script (reproduced below and in tokens.md §2). Grepped the prototype body for every selector in the ticket's required pair list to confirm real font-size/weight before classifying each pair as body (4.5:1) / large (3:1, only for text ≥24px regular or ≥18.66px bold, checked against the actual CSS, not eyeballed) / alert (7:1, allergen-context text) / decorative (icon glyphs and fills that aren't text).
5. For every FAIL, searched for a fix by scaling the failing color 1% at a time toward black (for a foreground) or the direction needed (for a background) until it cleared the target, then re-checked the candidate against every other pair sharing that token so a single proposed value could be recommended where possible (this worked for `--ink-3`, which fixes all 4 backgrounds with one value, and for `--danger`, which fixes both the alert-category rows with one value).
6. Grepped the whole file for `var(--brand)`, `var(--brand-deep)`, `var(--brand-tint)`, and `#f4b48f` to build the scarcity table (tokens.md §3), and separately for `var(--danger)`, `var(--rose)`, and `var(--ai)` to verify the three hard-rule boundaries recorded in §4 (allergen-red exclusivity, rose/danger separation, AI-purple exclusivity, freshness-ring ramp). All four boundaries held with zero crossover.
7. Measured tap targets (tokens.md §5) from the literal CSS: explicit `width`/`height` used directly where set; where not set, `height = font-size × line-height + padding + border`, with a line-height assumption of 1.2× font-size. That assumption was chosen because it exactly reproduces the M3-E0-T1 reviewer's own measured estimates (`.leglink` ~15px → 14.4 computed, `.toastUndo` ~24px → 24.4, `.chip` ~34px → 33.6, `.loc` ~35px → 34.6), so it is not a fresh guess, it is the same method the prior review implicitly used, made explicit and applied consistently to every remaining control.
8. Grepped for `transition`, `animation`, `@keyframes`, and `prefers-reduced-motion` across the whole file for the motion table (tokens.md §6). Zero `prefers-reduced-motion` matches, confirming the review's finding still holds.
9. Compared design-direction §2's v1 dark-mode table against both the v1 light values it documents and the v2 light values actually shipped, to build the dark-mode-readiness section (tokens.md §7).

## Contrast script (reproduced)

```js
function hexToRgb(hex){hex=hex.replace('#','');const n=parseInt(hex,16);return [(n>>16)&255,(n>>8)&255,n&255];}
function relLum([r,g,b]){const f=c=>{const s=c/255;return s<=0.03928?s/12.92:Math.pow((s+0.055)/1.055,2.4);};
  const [R,G,B]=[f(r),f(g),f(b)];return 0.2126*R+0.7152*G+0.0722*B;}
function contrast(h1,h2){const L1=relLum(hexToRgb(h1)),L2=relLum(hexToRgb(h2));
  const l=Math.max(L1,L2),d=Math.min(L1,L2);return (l+0.05)/(d+0.05);}
function composite(fgHex,alpha,bgHex){const [fr,fg,fb]=hexToRgb(fgHex),[br,bg,bb]=hexToRgb(bgHex);
  const mix=(f,b)=>Math.round(alpha*f+(1-alpha)*b);return {r:mix(fr,br),g:mix(fg,bg),b:mix(fb,bb)};}
```

Run via `node -e` with the token hex table inlined; full pair list and the darkening search loop are in `tokens.md` §2's fix table. All arithmetic was re-run and cross-checked before writing the final numbers into `tokens.md`.

## Honest gaps

- **Photo-scrim and glass-tag composites rest on a stated assumption**, not a measurement: the prototype hotlinks live Unsplash photos (already an open item, OQ-D8, for licensing reasons independent of this ticket), so there is no single true luminance to composite against. I assumed a 50%-grey mid-tone photo (`#808080`) for both the darkest `.scrim` stop and the `.tag.glass` chips. This is a deliberately conservative middle value, not a photographic measurement of the specific hotlinked images, and is called out inline in tokens.md §2 exactly where it's used. If the real photos run lighter than mid-tone in their upper thirds (where the glass tags sit), the true contrast could be lower than reported; if darker, higher. Both composited pairs pass with comfortable margin (9.23 and 10.64 against a 3:1/4.5:1 target), so a moderate swing in the photo assumption is unlikely to flip either verdict, but this was not independently confirmed against the actual hotlinked files.
- **The row-24 and row-25 brand/brand-deep fixes are the two least clean in the fix table.** Row 24 (white on `--brand` for the primary CTA) has a clean, no-new-hex fix (swap the resting background to `--brand-deep`), but it surfaces a secondary question this ticket doesn't resolve: what becomes of the button's pressed state, since `--brand-deep` would then be the resting color, not the darker pressed one. Row 25 (the loop banner) has no clean single-token fix at all without either weakening two already-passing pairs that share `--brand-deep`, or recoloring the banner text off-brand entirely; both options are laid out in tokens.md but neither is decided here, per rule 4 (this is presented as a PROPOSED, not resolved).
- **The `.noneopt.on` green-check item (tokens.md §4, item 2) is presented as two viable options rather than one recommendation.** I could not find a principled way to pick between "keep, it's a declaration not a verdict" and "swap to neutral, because a reviewer already flagged the visual proximity to the banned pattern" without making a product call that belongs to the PO, so both are written up for a decision rather than settled.
- **The reconciliation between this audit's "10 terracotta CSS rules" and the M3-E0-T1 review's "nine remain"** is explained (active-nav text-color and icon-stroke split into two rows here vs. one combined item there) but not independently confirmed against the reviewer's own working notes, since those aren't in the repo beyond the summary table in `M3-E0-T1.review.md`. The semantic content is identical either way (same nine roles, same KEEP verdict on all of them).
