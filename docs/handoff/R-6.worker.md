  `https://www.fsis.usda.gov/shared/data/EN/foodkeeper.json`,

- `https://catalog.data.gov/dataset/fsis-foodkeeper-data` (a different host) answered
  `200 OK` throughout, from the identical client — confirming this is not a general
  network outage in this session, just that specific host/CDN.
- Checked `https://data.amerigeoss.org/dataset/fsis-foodkeeper-data1` (an independent
  open-data mirror site) purely to see whether it hosted its own copy: it does not, every
  resource entry there points back to the same blocked `fsis.usda.gov` URLs.
- **Deliberately not done:** substituting an unofficial third-party GitHub repo's copy of
  FoodKeeper data. The ticket names one specific source; a third-party copy cannot be
  checksum-verified against it while the source is unreachable, so using one would trade a
  disclosed gap for an unverifiable, undisclosed one. Flagged as a RESEARCH REQUIRED
  judgment call for the architect, not a decision this worker made unilaterally.

**No rule-17 stop occurred.** The dataset asked for nothing (no account, no key, no
special terms, no payment) — the block is a network-access failure, distinct from the
gate the ticket asked this worker to watch for.

## Escalations / things I am least sure about

1. **Whether the Akamai block is specific to this sandbox's egress or would reproduce
   from any automated environment.** It is consistent with the common pattern of federal
   sites blocking cloud/datacenter IP ranges wholesale, which would mean it reproduces from
   *any* CI runner or cloud sandbox, not just this one — but I have no way to confirm that
   without trying from a different network (e.g. Andy's own machine). If it turns out to be
   this-session-specific and transient, a retry might just work.
2. **The `CATEGORY_KEYWORD_MAP` and the field-name-guessing heuristic in the script are
   unverified engineering guesses**, not measured. If FoodKeeper's real schema uses very
   different category vocabulary than the guessed keyword list, the matching logic in
   `classifyAgainstFoodKeeper` may need real rework, not just a data drop-in, once the file
   exists. I flagged this repeatedly in the script and the findings doc rather than
   quietly hoping it's close enough.
3. **Whether the "eggs → dairy" and "salmon → meat" bucket assignments for the Chen items
   are the right call**, or whether FoodKeeper (or a future revision of our own fixture
   taxonomy) treats eggs and seafood as their own categories. This only matters once real
   matching is possible; flagged in the script's own comment rather than decided quietly.
