# BUG-005 worker report

## What changed
- `apps/mobile/metro.config.js`: appended two RegExps to `config.resolver.blockList`, after Expo's own entries (a spread of the existing list, not a replacement):
  - `^<workspaceRoot>/.claude(?:/.*)?$` (any path at or under `<workspaceRoot>/.claude`)
  - `^<workspaceRoot>/.git(?:/.*)?$` (any path at or under `<workspaceRoot>/.git`)
  Both are built with `path.join` and `path.sep`, escaped for RegExp, so they work with the platform separator on Windows and Linux. They are anchored to the workspace root, so `apps/mobile/.claude` or `.github` are not blocked. A comment in the file explains the why.
- `apps/mobile/src/tooling/metro-config.test.ts` (new, 5 tests).
- No vitest config change was needed: the root include `apps/*/src/**/*.test.ts` already covers it. The CommonJS config loads through `createRequire`.

## Deviation
I did not use Metro's `exclusionList` helper. `metro-config` is not a direct dependency of `apps/mobile` under pnpm isolated linking (`require.resolve` failed), and adding a dependency needs approval (rule 11). The helper only escapes separators into a RegExp, so plain RegExps are equivalent. Expo's defaults (`.expo/types`, `.expo/web/cache`, `__tests__`, android/ios build dirs) are kept, and the test asserts two of them.
