# M3-T1 review: Expo app scaffold, design tokens module, tab shell with Menu placeholder, fixture identity client

**Reviewer:** independent Sonnet session, read-only. **Branch:** `m3-t1-expo-scaffold` @ `d6bfc48`. **Baseline:** `main`. Committed by the architect at acceptance (CLAUDE.md rule 29); the re-review outcome is appended at the end.

## Verdict

**PASS WITH FIXES.** The scaffold, tokens, shell and fixture client are solid, well tested, and the D-021 palette is exact. One invariant-enforcement gap (F1, the boundary lint can be bypassed by a relative import) must be closed before DONE, plus two scope and process items (F2, F3) need architect disposition. Nothing here is a safety, secrets, or product-scope problem.

## Findings

**F1 (major) The apps/mobile domain-boundary lint can be bypassed by a relative import.** `eslint.config.js:142-179`, `apps/mobile/src/lint-rules/domain-boundary.test.ts`. The rule uses only `no-restricted-imports` on the specifier string. A file at `apps/mobile/src/scratch-boundary-probe.ts` importing `../../../packages/domain/src/inventory/ledger` passes `tsc -b --force` and `eslint` cleanly; `apps/mobile/metro.config.js:20-27` sets `watchFolders` to the workspace root, so Metro would bundle it too. `packages/domain`'s own block (`eslint.config.js:113-124`) already uses `import-x/no-restricted-paths` for exactly this reason. Fix: add an `import-x/no-restricted-paths` zone (target `apps/mobile/src` and `apps/mobile/app`, from `packages/domain/src`) alongside the existing rule, and extend the boundary test to prove a relative-path import is rejected (on-disk fixture if the in-memory Linter cannot resolve paths).

**F2 (minor) File scope:** `packages/adapters/package.json` and `packages/adapters/tsconfig.json` changed (domain moved to dependencies, contracts added, a project reference). The ticket lists `packages/adapters/src/**` only. Small, necessary, disclosed, still a rule-14 excess. Disposition: architect ratifies at acceptance.

**F3 (minor, process) "No new fixtures" was not followable:** no inventory fixtures existed anywhere. The worker built `packages/adapters/src/inventory/fixture-inventory-items.ts` through the real ledger functions rather than hand-typed numbers, and flagged it. Rule 25's stop-and-escalate path fitted better than reason-and-flag, but the outcome is low risk and transparent. Disposition: accept; the architect decides whether this becomes the real `tests/fixtures/inventories/` corpus or is superseded by the M2-T1 endpoint.

**F4 (minor) Android variable-font weight rendering unverified on device.** Honestly flagged by the worker; nothing typography-sensitive ships in M3-T1. Check before M3-T2.
