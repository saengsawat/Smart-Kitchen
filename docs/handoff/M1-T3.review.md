### Findings
- **F1 (HIGH, test gap):** the volume anchor was pinned by nothing — property tests asserted only *self-consistency* (expected factors derived from the registry itself; all hand-verified tests were ratio tests). Mutation proof: substituting the **imperial gallon (a 20% error in every volume unit) passed all 62 unit tests**; a 1-in-3.8e9 gallon nudge passed too. Required: absolute ground-truth assertions from independently written literals + negative assertions (imperial gallon, metric cup, imperial cup absent).
- **F2 (MEDIUM, defect):** `makeBridge` threw (`SyntaxError`) on finite ratios rendered in exponential notation (`1e-7`, `1e21`) — a private weaker duplicate of `decimalToRational` without exponent handling, violating the module's never-throws contract.
- **F3 (MEDIUM, contract violation):** `addQuantities`/`neededQuantity` leaked the caller's raw alias as the result unit (`"pounds"`, `"POUNDS"`) instead of the canonical symbol — downstream the ledger compares units by exact string equality, so this risked spurious `MIXED_UNITS`/divergent balances.
- **F4 (LOW/MEDIUM, design):** `compareQuantities` was not antisymmetric (rounded `b` into `a`'s unit before comparing): `(1n tsp vs 0n cup) → 1` but reversed `→ 0`. Recommended exact cross-multiplication.
- Opinion items: round-half-even policy **endorsed** (truncation would systematically under-buy in shopping-gap math); supported-unit set **endorsed**; micro-unit interop by documented convention rather than coupling **endorsed**; suggested narrowing raw `Rational` helpers out of the root barrel (architect endorsed, applied).
