1. Workflow: what a household does

Six stages, read left to right. The loop at the right edge is the point of the product: buying food and cooking food both change the pantry, so the pantry stays true.

BUILT works on the phone against the real server PARTIAL works, with a stated gap PROTOTYPE designed in the v6 prototype, not built NOT BUILT not built, or later

Where the loop breaks today

  • Decide (stage 4) has nothing to decide with. There are no recipes in the app, and the Menu tab is a placeholder. The allergy engine is built and tested, but it has no recipes to check.
  • Allergies stay on the phone. They are not saved on the server, so a scan says allergens are "not checked". Saving them waits on A3 (who enters and who sees allergies).
  • Shop (stage 5) only knows pantry items. A shopping row works out the gap against one pantry item. Nothing turns a plan into shopping rows yet, and you can't type your own row yet.
  • Cook (stage 6) doesn't take food out of the pantry. The cook sheet is designed in the prototype; the ledger already has the right row type (USE_IN_MEAL), but nothing writes it.
  • Sign-in is a stand-in. The app runs as fixed test people. Real accounts and hosting come before the friends beta.

3. Architecture: how it is built today

Three parts that run (phone app, API server, database), three shared code packages, and one outside service. Amber dashed items are PROPOSED by the revisit, not built.

The rules the architecture enforces

  • The pantry is a ledger. Quantities change only by adding a row (bought, used, corrected, thrown out). A correction or an undo is another row, never an edit. That is why history and the correction-rate number can be trusted.
  • Households can't see each other. Every request runs inside one household's transaction, and the database itself refuses rows from another household even if the code forgets to filter.
  • Safety math is plain code, never AI. Allergen checks, quantities and shopping gaps are deterministic and tested. Allergen checks can say "contains" or "not checked", never "safe".
  • Every write can be retried safely. The phone sends a key with each write; sending it twice does nothing the second time.
  • Outside services sit behind ports. Open Food Facts can be swapped or faked in tests; the test suite never calls the internet.
